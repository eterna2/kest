Kest Zero Trust Lab

A local Docker-based playground for testing Zero Trust execution with real SPIFFE identities, OPA/Cedar policies, and OpenTelemetry auditing.

🚀 Services

  • SPIRE: Standardized identity framework for workloads. Provides JWT-SVIDs.
  • OPA: Open Policy Agent for Rego-based authorization.
  • Cedar-Agent: High-performance authorization for application-level permissions.
  • OTel Collector: Centralized sink for audit logs and traces.
  • Workload: A Python container configured to use the kest.core library.

🧪 Architecture & Testing Nuance

The lab is configured to support Container-Native SPIRE attestation for integration testing.

SPIRE's unix workload attestor relies on the Linux kernel's SO_PEERCRED mechanism to securely extract the PID, UID, and GID of connecting processes.

The Solution: Kest gracefully delegates test-live execution directly into the hop1 container (docker compose exec hop1 pytest...). This ensures tests run in the identical PID namespace hierarchy as the deployment, providing a 100% accurate integration test environment that is immune to local WSL/VM networking abstractions.

The execution environment is now natively resilient and fully mimics a strict isolated integration node environment.

🧪 Included Integration Tests

The showcase/kest-lab/tests/ directory hosts a comprehensive, async-first test suite validating the core toolkit. The suite automatically tests:

  1. OPA Policy Enforcement (test_opa_enforcement.py): Tests asserting that requests missing a valid SPIFFE SVID, or lacking required role claims, are actively blocked by the OPA sidecar.
  2. OpenTelemetry Context Propagation (test_otel_propagation.py): Tests verifying that W3C distributed trace IDs automatically traverse across the multi-hop network (hop1 -> hop2 -> hop3) using standard contextual extraction/injection and appear unified in the OTel collector and Kest's audit lineage.
  3. Cedar Authorization Validation (test_cedar_abac.py): Tests verifying fine-grained attribute-based access control (ABAC) execution using Cedar policies against structured identity contexts.
  4. Multi-Hop Resiliency (e2e_test.py): End-to-end tests ensuring complex data exchange paths remain stable under variable network or token rotation scenarios.
